## S1 确认开发环境 约 30 分钟

- [ ] 在双系统 Linux 中检查 Python、C++ 编译器和 Git。

动文件：创建 `docs/env_system.txt`。  
做法：在终端运行 `cat /etc/os-release`、`uname -r`、`python3 --version`、`g++ --version`、`git --version`，缺少什么只补什么。  
检查：Python 和 g++ 能输出版本；将版本、报错和补装情况写入记录。

## S2 手动运行一个 A+B 程序 约 30 分钟

- [ ] 编写 C++ 程序，编译后分别运行两组输入。

动文件：创建 `examples/a_plus_b.cpp`，以及 `problems/a_plus_b/tests/01.in`、`01.out`、`02.in`、`02.out`；编译产物放 `work/stage1/`。  
做法：01 为 `1 2 → 3`，02 为 `-2 5 → 3`，输出文件末尾带换行。此时只准备文件，题目 JSON 在第二阶段补齐。  
检查：两次运行输出正确；你能解释标准输入与标准输出，并将文件同步给队友。

## S3 用 Python 重复上述流程 约 60 分钟

- [ ] 写脚本调用编译器，成功后分别运行两组输入并打印退出码、实际输出和预期输出。

动文件：保留已有的 `scripts/__init__.py`，编写 `scripts/run_demo.py`；保存记录到 `artifacts/system/stage1_demo.txt`。  
做法：学习 `subprocess` 当前所需用法，先将流程写在这个脚本中；编译失败则显示错误并停止。  
检查：从项目根目录运行 `python3 -m scripts.run_demo`，完成一次编译和两次正确运行；你能指出编译、输入、输出各自对应的代码。这里只验证自写样例，普通等待超时不代表 CPU 时限或沙箱已完成。

## S4 检查执行工具可行性 约 30 分钟

做法：从 [Isolate 官方项目](https://github.com/ioi/isolate) 开始，记录命令与错误。30 分钟仍卡住时，留下问题并继续 S5。  
检查：记录清楚区分已验证、未验证和阻碍；不能仅因工具安装成功就声称已验证资源限制。

## S5 与队友共同验收 约 30 分钟
