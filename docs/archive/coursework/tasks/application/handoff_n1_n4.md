# AlgoOS 应用负责人接手清单

**汇报前优先级：收到可复现版本后 24 小时内，回传本机复跑和 Web 演示结果。** 如遇依赖或启动问题，尽早回传状态和第一个报错，最迟仍在 24 小时内反馈。先交演示材料，云端环境另行确认。

1. **核对交接版本。** 用系统负责人提供的分支和提交号开工。先读[部署说明的 N4 接手入口](../../ops/deployment.md#n4-应用负责人接手入口2026-11-15)，用 [newplan 状态表](../system/new_plan_1110.md#n1n4-任务与验收修订)核对已完成和待验收的范围。
2. **独立复现一次。** 从项目根目录执行部署说明里的 N4 批次命令，无需逐项重做 N1–N3。预期 AC、WA、CE、SE 的评测任务数为 2、2、0、0；保留终端汇总和证据路径。失败时记录运行环境、首个报错和证据路径。
3. **运行并演示已有页面。** 从项目根目录执行 `python3 -m scripts.demo_web`，打开 `http://127.0.0.1:8765/`。先点开 AC 看两个节点，再点 CE 看未派发。预演时可点一次「运行内置样例」，等页面显示「本机内置样例实跑」，保存截图或录屏。现场可直接使用实测记录回放。用 Ctrl+C 结束页面服务。
4. **确认部署环境。** 复现后核对目标节点的系统、架构、依赖和私网连通性。按部署说明推进，分别记录本机独立复现和云端验收结果。

可以把这句话交给接手的 AI：「按交接提交读取 N4 部署说明和 newplan，按清单运行、复现和演示，记录异常与证据。保留旧记录，分别标注本机验证和云端验证；需要改代码或方案时将问题交回系统负责人。」

**竞赛题演示：**在根目录运行 `work/n32_runtime/venv/bin/python -m tests.n34_eval_batch --lazy-gold --actor 本人姓名`，刷新页面，确认《The Lazy Cow》显示 AC 11/11、节点点数 6 / 5，以及单点墙钟、CPU 和峰值 RSS。Web 的「运行内置样例」按钮只重跑 A+B；竞赛题区读取已生成的独立实测记录。现场可直接回放。

**回传格式：**提交号、复跑通过项或阻塞、两个批次的证据路径、1 张竞赛题页面截图或一段短录屏。录屏可按「A+B 的 AC/CE → 竞赛题 11 点分发与指标」操作。只需运行、复现、检查、演示；需要改代码或调整方案时，反馈给系统负责人。
